## Theorie

### Argumentationskette

**AES-256-CBC**
 Schnell bei großen Datenmengen, RSA wäre zu langsam.

**Eigener Key pro Datei**
 Isolierung: Fällt ein Key kompromittiert, sind die anderen sicher. Mit IV=0 verhindert es Muster bei Key-Wiederverwendung.

**AES-Key RSA-verschlüsselt**
 Verhindert, dass Opfer Keys einfach ausliest – nur privater Key des Opfers kann sie entschlüsseln.

**An Datei angehängt**
 Elegant: Keine separaten Files. RSA-2048 = immer 256 Bytes → letzte 256 Bytes sind der verschlüsselte AES-Key.

**Victim Private Key AES-verschlüsselt**
 Muss am System bleiben, aber unverschlüsselt wäre er wertlos für Konkurrenten ohne AES-Key.

**Globaler RSA Masterkey**
 Zentrale Kontrolle: Eine Geheimnis für alle Opfer. Mit globalem privatem Key kann Angreifer alle `aes_victim_key`s wiederherstellen.

`ryuk.ransom.sh` verschlüsselt `test.txt` und erstellt im Ordner folgende Dateien:

```shell
187hahaxd@Mac Ryuk Folder % tree
.
├── rsa_victim_private.pem
├── rsa_victim_public.pem
├── ryuk_decrypt.sh
├── ryuk_ransom.sh
├── test.txt
└── test.txt.enc
```

NUR mithilfe des `rsa_victim_private.pem` kann die Datei wieder entschlüsselt werden. Diese wird normalerweise nur übergeben, wenn bereits gezahlt wurde.

Nun wird durch `ryuk_decrypt.sh`, welches als Argumente `rsa_victim_private.pem` und das verschlüsselte File (in dem Fall `test.txt`) braucht, das verschlüsselte file mit der Endung `.enc` wieder entschlüsselt.
